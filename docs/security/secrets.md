# Secrets inventory (P12a, issue #27 criterion 9)

Every secret the system has, where it lives, who reads it, how it rotates and what a leak lets an attacker do. Invariant 6: no secret in the repository, a log, the manifest, `ingest_batch`, archive metadata, a fixture or an image. Secrets on the VPS are **files**, never environment variables; the build context is an allowlist. The drill that exercises this table is `docs/runbooks/secrets-rotation.md`; run it after any change here and at least once a year.

The `Where` column holds a location, never a value. Nothing in this repository names a person; evidence of a secret's existence is `sudo stat` on the file, not its content.

## On the VPS: `/etc/rws/secrets` (directory root 0700, each file `root:<gid>` 0440)

Compose keeps a file secret's host owner and mode, so each file is readable by one group and only its consumer container has that gid (`group_add`, `deploy/compose.yaml`). Edit in place with `sudoedit`; never replace the file (the bind mount follows the inode). Check: `sudo stat -c '%n %a %U:%G' /etc/rws/secrets/*`.

## WireGuard and the owner channel

| Secret | Where | Read by | Rotation | If it leaks |
|---|---|---|---|---|
| WireGuard server private key | `/etc/wireguard/wg0.key`, root 0600 | `wg-quick@wg0` | Generate a new key, put the new public key in every device's config: a new key invalidates every peer config, so this is a re-provisioning of all the owner's devices (`docs/runbooks/owner-device.md`) | An attacker can impersonate the server to a device, not read the VPS. The owner site also has `basic_auth` and a `tls internal` certificate |
| Peer private keys | **Only on the owner's devices.** Generated there, never sent, never on the VPS; the server holds public keys only (`rws-wg-peer`) | the device | `rws-wg-peer revoke <name>` removes the peer at once, then add a new one. Drill step 4 | A holder of the key plus the `basic_auth` password reaches the owner view. Revoke the peer, rotate the password |
| Preshared key of each peer | `/etc/wireguard/wg0.peers.conf`, root 0600, with the peer's public key; the client config is printed once by `rws-wg-peer add` | `wg-quick` | With the peer: `revoke` then `add` | Same as the peer key |
| Caddy `tls internal` root CA | the volume `caddy_owner_data` (`/data/caddy/pki/authorities/local/`); the **public** root certificate is exported to the owner's devices | caddy-owner | Delete the volume's `pki` directory and restart caddy-owner: a new root; re-import it on every device (`docs/runbooks/owner-device.md`) | Whoever holds the root key can mint certificates for the owner hostname; still needs a WireGuard path to use them |
| The owner's password manager entries (the `basic_auth` password, hc and S3 admin keys, restic password) | the owner's own vault | the owner | The owner's discipline; use a hardware-backed vault | Everything above |

## What is not a secret (and must not be treated as one)

The registry, the permission records (they hold the grantor organisation and where the e-mail is kept, never its text or a person's name), the `private_basis` of owner sources (ADR-0017: the clause, URL and date), the owner canary (`777777.777`), the RWS contact address and operator name (shown on the colophon) and the public WireGuard endpoint if it is ever published.

## Checks that keep this table true

- `scripts/gh-settings.sh --check`: no secret in the repository or the `production` environment.
- `gitleaks` over the full history (`security.yml`), with a planted key that must still fail (`scripts/gitleaks-planted.sh`).
- `deploy/tests/hardening.sh --prod` keeps the containers that hold these files read-only, non-root and without capabilities. The `hc_ping_key` is read before every ping, so its rotation never needs a restart.
- `sudo stat -c '%n %a %U:%G' /etc/rws/secrets/*` shows every file `440 root:rws-*` (bootstrap resets them), `/etc/wireguard/wg0.key` is `600 root:root`.
- Logs: the access logs delete the `Authorization` and `Cookie` headers (T-OWN-4); host scripts pass keys to `curl` through `-K -` on stdin, never argv (T-HOST-4); error and alert texts carry fixed codes only.
