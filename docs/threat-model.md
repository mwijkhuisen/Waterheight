# Threat model

**Version 3**, P1b (2026-09-29): adds the platform: the signed pull-based deploy chain (T-DEP-*), the host and its firewall (T-HOST-*), the off-site backups (T-BAK-*) and the watchdog (T-WD-1). Version 2.2, P1a: adds the capture recorder (T-CAP-*) and, after its reviews, the availability of its single process (T-CAP-8). Version 1 (P0b) covers what exists after Phase 0: the repository, CI, the agent set-up and the supply chain, and it records the owner channel (D22, ADR-0017) and the public ↔ owner boundary that later phases build. Every phase that changes the attack surface updates this file (A§12.2). Risks that are accepted rather than fixed are in [`risk-register.md`](risk-register.md).

## Assets

| Asset | Why it matters |
|---|---|
| **Repository integrity** (`main`, the `legacy-v0` tag, workflows, `CLAUDE.md`, the registry) | Every later agent follows `CLAUDE.md` and the registry; a poisoned workflow or registry entry propagates everywhere |
| **The CI root of trust**: `GITHUB_TOKEN`, pinned actions and binaries, the required checks `ci` and `security` | A compromised run could push code, tags or releases |
| **Deploy trust chain** (P1b): the signed release, the `production` environment, cosign identity | GitHub holds no server credential (ADR-0008); only signed digests may run |
| **Raw archive and database** (P1, P2) | The only copy of forecast runs, alert states and threshold versions nobody can refill (ADR-0003) |
| **Owner-audience data** (BE-3, LU-2/3/4, DE-2/3; later BE-1/2) | Terms allow personal use only (catalogue §0.8); any public exposure is a licence breach (invariant 11) |
| **The owner channel's secrets**: the WireGuard keys of the owner's devices and the server, the `basic_auth` password and its bcrypt hash | They are the only way into the owner view (A§11.5) |
| **Provider goodwill and credentials** (HIC, VMM tokens later) | Losing access loses coverage; tokens are Compose secrets only |
| **Visitor privacy** | No cookies, no analytics, no third-party requests (invariant 7) |

## Actors

- **The owner**: the sole maintainer, merger and owner-view user.
- **Build and review agents** (Claude Code, local or claude.ai/code): write code on `claude/*` branches, no production access, no WireGuard peer, never merge.
- **Outside contributors and attackers**: can open PRs and issues on the public repository, publish npm packages or GitHub actions, or compromise an upstream maintainer.
- **Providers**: publish the data and its terms; their payloads are untrusted input (invariant 3).
- **Visitors**: the public site (P4 onward); never the owner view.

## Trust boundaries

1. **Pull request → CI.** On `pull_request` the PR supplies the workflow files, the scripts and the allowlists it is checked with (P0a S8).
2. **Upstream → CI and installs.** Actions, npm packages and release binaries come from third parties.
3. **Repository text → agents.** Issues, docs, fixtures and provider strings reach model context.
4. **Branch → agent session.** The SessionStart hook runs whatever copy the checked-out branch holds.
5. **Public ↔ owner** (P2 onward). Public roles and outputs versus the `own_*` views, `rws_owner_api`, `/srv/rws/owner`, `api-owner` and the WireGuard-only owner site.
6. **Internet ↔ VPS** (P1b onward): Caddy, the capture egress allowlist, SSH.

| T-CAP-1 | 6 | SSRF through a registry entry, a provider redirect or a provider-supplied URL (Hub'Eau `next`, LU-5 resource `url`, data.public.lu `next_page`): the recorder is made to reach an internal or metadata address, or a host of another source | Fetch targets only from `registry/capture.yaml` (invariant 1); per-source host allowlist (no `off` source has a host); https only, no userinfo, no IP literal, port 443; every hop resolved and every answer required public (`net.BlockList`: IPv4 minus the special ranges; IPv6 only inside global unicast `2000::/3`, minus `2001::/23`, `2001:db8::/32`, `2002::/16` and `3fff::/20`, so IPv4-mapped and -translated forms such as `::ffff:0:a9fe:a9fe`, site-local `fec0::/10` and the rest of `::/8` are refused), and the undici Agent's connect-time lookup checks again and the connected peer once more, so the socket only ever uses a validated address; same-host redirects only, never to http, ≤ 3; provider URLs re-checked with the same rules plus a per-spec path pattern and a per-run cap; provider codes that fill a URL (FR-4 stations, FR-5 sections) are pattern-checked; tests with msw and with the undici transport | The nftables egress rules of P1b are the second layer; a network-specific NAT64 prefix inside `2000::/3` (DNS64) is not refused here and relies on those rules; test seams (a transport and an address check) are constructor arguments only, never env or config |
| T-CAP-2 | 6 | Resource exhaustion by an upstream: a huge body, a gzip bomb, stacked encodings, a slowloris, a ZIP/XML/CSV bomb | Raw bytes counted while streaming (25 MB, never trusting Content-Length); one gzip/br layer decoded with a 100 MB cap, stacked or unknown encodings refused; a total deadline per hop that starts only after the politeness wait, the DNS check and the byte-budget wait (so a wait never turns into a timeout), raced against the transport call and the body read, and the DNS check raced against a deadline of its own; the transfers of one request share twice the timeout, so a redirect chain cannot stretch a request to about 4 × the timeout; ≤ 2 connections per host; an in-flight byte budget (128 MB) for the 384 MB container, reserved per transfer right before the transport call (never across a politeness wait or a DNS lookup), where a request that fits passes a larger waiter; ZIP read from the central directory with real-size, ratio, total and CRC checks, streamed and never written by name; XLSX XML text capped at 8 MB per member and 16 MB in total while it is inflated; XML with any DOCTYPE/ENTITY refused and entities off; CSV row/column/field caps | Bodies are held in memory up to the byte budget (R-023) |

| T-CAP-6 | 6 | Abusing or being blocked by a provider (over-polling, burst on restart, a harvest hammering a host) | Budgets computed from the registry in CI (RWS ≤ 400 requests in any 60 min); no request without a contact User-Agent (exit 78); full-jitter backoff honouring Retry-After after a 5xx, 429, timeout or network error, after a 403 or 451 (a WAF block, which no longer counts as a success and is transient like a 429, so a daily spec retries hourly) and after a status outside 100–599, and a per-host breaker whose one half-open probe is a whole request (a same-host redirect hop included) and is released on every exit path, so a probe that ends on a DNS, redirect or cap error re-arms the breaker instead of latching it open; a request that waited for the byte budget checks its host again and is not sent if another request put the host into backoff meanwhile; no run on start, except that a missed tick runs once and a daily or weekly spec seen for the first time runs once (A§7.2 "once at first start"; staggered 15 s apart, 1 RWS request); seeds one request at a time and paced (FR-1 ≥ 2 s); a provider link is fetched at most once per run, so a looping `next` ends the walk, a capped FR-1 walk never asks for the same window twice unless it stalls (and then pages), and the FR-1 seed's page cap bounds the whole seed, rounds included, which end 31 days after the first; the smoke recorder is opt-in, capped and refuses under CI, and `healthz-smoke.sh` runs every role without the contact variables and under a 10 s timeout, and requires exactly exit 78 from `capture`, so it never starts the live recorder from a developer shell | Cloudflare in front of AGE may still block the VPS (catalogue §10 R7; `rws-reachability` in P1b) |

| T-CAP-8 | 6 | Availability of the single recorder process: one process captures every provider, so an unhandled rejection, an event-loop block, memory exhaustion, a latched breaker or a stall of a shared resource stops all capture at once;
