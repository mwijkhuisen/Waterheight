## Actors

- **The owner**: the sole maintainer, merger and owner-view user.
- **Build and review agents** (Claude Code, local or claude.ai/code): write code on `claude/*` branches, no production access, no WireGuard peer, never merge.
- **Outside contributors and attackers**: can open PRs and issues on the public repository, publish npm packages or GitHub actions, or compromise an upstream maintainer.
- **Providers**: publish the data and its terms; their payloads are untrusted input (invariant 3).
- **Visitors**: the public site (P4 onward); never the owner view.

## Trust boundaries

1. **Pull request → CI.** On `pull_request` the PR supplies the workflow files, the scripts and the allowlists it is checked with (P0a S8).
2. **Upstream → CI and installs.** Actions, npm packages and release binaries come from third parties. From P2b the nightly contract check also fetches three provider payloads live from a GitHub-hosted runner, six since P5a, eight since P5b, nine since P8a and eleven since P8b (T-CI-5). From P3, `geo.yml` downloads the pinned `basemaps-assets` commit from codeload.github.com (T-MAP-3), and the `e2e` job runs a third-party Playwright image (T-CI-6). From P6a, `geo.yml` also downloads the 16 OpenStreetMap extracts from download.geofabrik.de and three source tarballs (libosmium, osmium-tool, tippecanoe) from codeload.github.com, installs Debian packages for its tool image, and queries the EU-Hydro MapServer (T-GEO-1, T-GEO-2, T-GEO-5). From P6b the owner's host script `rws-rivers-refresh` fetches a signed `geo-YYYY-MM-DD` release over https from `github.com` and `api.github.com` and verifies it with cosign before anything is served (T-GEO-6).
3. **Repository text → agents.** Issues, docs, fixtures and provider strings reach model context.
4. **Branch → agent session.** The SessionStart hook runs whatever copy the checked-out branch holds.
5. **Public ↔ owner** (built in the database in P2a; in the publishers and the owner site from P9). Public roles and outputs (`rws_api`, `rws_publish`, the `pub_*` views, `/api/v1/health*` and, from P4a, the data routes of the API) versus the `own_*` views, `rws_owner_api`, `/srv/rws/owner`, `api-owner` and the WireGuard-only owner site. In P2a the boundary is enforced by grants on two `security_barrier` view families and tested with real logins and canaries; the loader (`rws_load`) sits on the private side and can read the registry but never write it.
6. **Internet ↔ VPS** (P1b onward): Caddy, the capture egress allowlist, SSH. From P3 also the basemap job's egress to the two Protomaps hosts and the tile files that Caddy serves (T-MAP-1, T-MAP-2). From P4b the `api` is public through Caddy (T-API-2) and Caddy serves the web app, the nine pages per language and a real 404 (T-WEB-1, T-WEB-2, T-WEB-4). From P6b Caddy also serves the river tiles, the rivers manifest, the reaches file and the ODbL download from two read-only mounts (T-GEO-7).
