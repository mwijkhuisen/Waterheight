# ADR-0016: Map rendering under a strict CSP

- **Status:** Accepted (P3, issue #18)
- **Date:** 2026-10-01
- **Source:** `docs/plan/ARCHITECTURE.md` §13 (stub), PHASES P3; evidence in `apps/web/e2e/map.spec.ts` and the CI job `e2e`

## Context

MapLibre GL JS 6 removed its UMD and CSP bundles (catalogue §8 C23), and whether `@protomaps/basemaps` 5.7.2 works with v4 tiles was unverified (catalogue §5.1). The site-wide CSP (A§12.2) carried `blob:` in `img-src` and `worker-src` on the assumption that MapLibre needs it. Every later web phase inherits the map set-up and the CSP decided here.

## Decision

**Worker.** MapLibre 6.11.1 picks its worker URL as `setWorkerUrl()` or `new URL('./maplibre-gl-worker.mjs', import.meta.url)`, starts a same-origin URL as `new Worker(url, {type: 'module'})`, and wraps only a cross-origin URL in a `blob:` module. Vite moves `import.meta.url` to our chunk, so the default URL would 404; we import `maplibre-gl/dist/maplibre-gl-worker.mjs?worker&url` (Vite builds the worker and its shared code into one ES module file, `worker.format: 'es'`) and call `setWorkerUrl()` with it. The worker is `/assets/maplibre-gl-worker-<hash>.js`, same-origin, never a blob. Chromium and WebKit report it as an absolute same-origin URL, Firefox as the root-relative path given to `new Worker`.

**Final CSP** (site-wide; `deploy/web/site.caddy`, A§12.2, `test/verify-prod.test.ts`):

```
default-src 'none'; script-src 'self'; style-src 'self'; img-src 'self' data:; font-src 'self'; connect-src 'self'; worker-src 'self'; manifest-src 'self'; base-uri 'none'; form-action 'none'; frame-ancestors 'none'; object-src 'none'; upgrade-insecure-requests; report-to csp
```

Only tightened: `blob:` is gone from `img-src` and `worker-src`. Evidence, all three browsers (Playwright 1.63.0: Chromium 153, Firefox 155, WebKit 26.6):

| CSP variant | Result |
|---|---|
| A§12.2 as it was (`img-src 'self' data: blob:`, `worker-src 'self' blob:`) | all specs pass |
| `img-src 'self'`, `worker-src 'self'` | every map spec fails in every browser with `img-src data` violations: the SVG icons in MapLibre's CSS (attribution and navigation controls); no `worker-src` violation |
| **`img-src 'self' data:`, `worker-src 'self'`** (chosen) | all specs pass: 0 `securitypolicyviolation` events, no CSP console message, no CSP-blocked request, every request same-origin |

MapLibre still has a `blob:` image path, used only when `createImageBitmap` is missing; all three engines have it. `style-src 'self'` works without `'unsafe-inline'`: MapLibre and React set styles through the CSSOM, and Vite emits every style as a file (`assetsInlineLimit: 0`).

**Style.** `@protomaps/basemaps` 5.7.2 works with the v4 tiles (build `20261001`, tiles 4.15.2): both styles validate against `@maplibre/maplibre-gl-style-spec` 26.4.4, the exact version maplibre-gl 6.11.1 resolves, and render z4–z14 of the Lobith fixture with no map error. Flavour `white` (owner decision 2026-10-01; 5.7.2 has no "muted" flavour); labels from `name:nl` / `name:en`. The styles are generated by `tools/geo/basemap/build-style.ts`, committed, and bundled into lazy chunks per language.

**Planet z0–6 and regional z0–14.** One style, two sources: `planet` (the world, z0–6) as an underlay at every zoom (overzoomed above z6, so the map is never blank outside the Rhine-basin box), with its labels ending at z7; `basemap` (bbox `1.5,45.8,12.5,54.0`, z0–14) from z7 up, drawn over it, with no background layer of its own. Five planet label layers whose own range starts at z7 or later are dropped; the style tests pin the list.

**Glyphs and sprites.** Committed copies of `protomaps/basemaps-assets@028c18f` (fonts: SIL OFL 1.1; sprites: MIT, from tangrams/icons, © 2017 Mapzen) under `apps/web/public/assets/map/028c18f/`: Vite copies them into the web image, which serves them as immutable `/assets/map/028c18f/…`. Every file is listed in `SHA256SUMS`, whose sha256 `registry/basemap.yaml` pins; `geo.yml` re-checks the copy against the upstream commit.

**URLs.** The build and the styles hold no hostname: tile, glyph and sprite paths are root-relative and put on `location.origin` at run time, and the tile files come only from `/tiles/manifest.json` after `parseTilesManifest`. The same build can later serve the owner site (A§10).

**Attribution.** The style's own constant, "© OpenStreetMap contributors" (linked to https://www.openstreetmap.org/copyright) · "Protomaps". The pmtiles protocol runs with `metadata: false`, so the archive's own attribution HTML never reaches MapLibre's attribution control, which renders HTML.

**Time.** `lib/time` imports `temporal-polyfill/global` only where `Temporal` is missing. WebKit 26.6 now ships Temporal, so the e2e deletes it before page scripts run to prove the polyfill path.

**Fallback.** If a later `@protomaps/basemaps` release or tiles version breaks the style tests, pin the last compatible basemaps version (it only generates the committed JSON), or maintain our own style JSON in `tools/geo/basemap/`. Neither changes the CSP.

## Consequences

- No `blob:` anywhere in the CSP. A new library that needs one is a CSP change and needs an ADR (invariant 10).
- MapLibre is a lazy chunk of about 1.04 MB (283 KB gzip) plus a 510 KB worker file, never in a page's initial load (`apps/web/test/map-build.test.ts`).
- The web image grows by about 18 MB of glyphs (the Devanagari stack is mostly copies of the regular one).
- Headless WebGL2 works in all three engines through software renderers (Chromium: SwiftShader; Firefox and WebKit: Mesa), so the e2e needs no GPU. Headless Firefox needs an X display for any GL context ("Exhausted GL driver options" without one, reproduced locally by unsetting `DISPLAY`): CI runs Playwright under the image's own `xvfb-run`, and the Firefox project sets `webgl.force-enabled` so Firefox accepts the software renderer. Both change the runner, not an assertion: the page still creates its own WebGL2 context, and the first spec fails if it cannot.
